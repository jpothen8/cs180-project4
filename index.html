A.1

Shoot the pictures

I took three overlapping photo pairs of different scenery, one of the trees near the Social Sciences building, one of my kitchen, and one of my living room. I resized all of the pictures so that the longest side was 1600 pixels to keep processing manageable while retaining enough detail to choose corresponding points. A homography is exact for points on a common plane, or for a camera rotating around a fixed center of projection. All the scenes include objects at different depths, so it is especially important to keep the camera center fixed. If the camera translates, nearby and distant objects will shift differently so the single homography wouldn't align everything. Thus, I tried my best to always rotate around the center of the camera rather than the center of the device I'm using (my phone).

Recover homographies

A homography is a 3x3 matrix that maps a source point to a reference point in homogeneous coordinates. In order to obtain the reference image coordinates after multiplying H by [x,y,1], the first two coordinates are divided by the third to get a [x*,y*] 2D coordinate. Multiplying every entry of H by the same nonzero value leaves the mapping unchanged, so my implementation fixes the bottom-right entry to 1 and solves for the other 8 entries.

In the image, I pick reference points visible in both images, and each matching point pair gives two equations. Rearranging the equations for u and v gives the two rows of Ah=b shown above. Four pairs can determine the eight unknowns, but extra pairs provide more constraints and thus reduce sensitivity to an individual inaccurate matching point, and I use numpy's least squares solver to solve the overdetermined linear system. This minimizes the sum of squared residuals of Ah=b, but that does not necessarily mean it's minimizing the geometric reprojection error.

I had 10, 9, and 13 pairs for the trees, kitchen, and living room pairs, respectively, which created 20x8, 18x8, and 26x8 systems to solve. The fitted reprojection RMSEs are 2.69, 1.84, and 3.55 pixels, which measure the disagreement with the same points used to estimate H. These errors could be caused by inaccuracies in placing the paired points or correspondences that can't be explained by a single homography (e.g. parallax from camera translation, or lens distortion).

Code · linear system and least-squares fit
def homography_system(im1_pts, im2_pts):
    p = np.asarray(im1_pts, dtype=float)
    q = np.asarray(im2_pts, dtype=float)
    if p.shape != q.shape or p.ndim != 2 or p.shape[1] != 2 or len(p) < 4:
        raise ValueError("Need at least four matching (x,y) points in each image")
    A = []
    b = []
    for (x,y), (u,v) in zip(p, q):
        A.append([x, y, 1, 0, 0, 0, -u*x, -u*y])
        A.append([0, 0, 0, x, y, 1, -v*x, -v*y])
        b.extend([u, v])
    return np.array(A), np.array(b)


def computeH(im1_pts, im2_pts):
    A,b = homography_system(im1_pts, im2_pts)
    h, residuals, rank, singular = np.linalg.lstsq(A, b, rcond=None)
    if rank < 8:
        raise ValueError("These points do not determine a homography")
    return np.append(h, 1).reshape(3,3)
A.3

Warp the images

Inverse mapping · source pixel centers at integer coordinates · explicit validity mask

destination (x, y, 1)ᵀ → H⁻¹ → divide by homogeneous coordinate → sample source
Output array (column, row) = reference coordinate − (xₘᵢₙ, yₘᵢₙ). Source warp bounds: (371, −276) to (2278, 1292), inclusive.

In order to warp the images, I use the inverse mapping. First, the four pixel center corners of the source image are transformed by H to determine the output bounds, and the minimum coordinates are rounded down and the maximum coordinates are rounded up so the canvas has enough space to contain the entire transformed image. I allow negative coordinates because the warped photo can extend above or to the left of the reference image. For each output pixel, the canvas origin is added to its array coordinates to recover its position in the reference coordinate system. Multiplying that point by H inverse and dividing the first two coordinates by the third, as I explained above, gives the location to sample in the source image. In this way, I avoid the gaps that can happen when the source pixels are mapped forward to scattered destination locations. A separate validity mask records whether the mapped source location actually lies in the source image, and locations outside the source stay empty while genuine black pixels inside the source remain valid.

Now, we have to actually figure out the color values when the inverse homography outputs source coordinates that are not clean whole numbers. The first method I implemented was nearest-neighbor interpolation, which rounds the mapped source coordinates to the closest integer pixel. It just uses this one source value and is fast, but small changes in the mapped position can abruptly switch which pixel is selected. This can make diagonal edges or enlarged details look somewhat blocky.

The second method is bilinear interpolation, which uses the four neighboring source pixels, thought of as single point values instead of as squares. If dx and dy are the fractional parts of the source coordinates, their weights are (1−dx)(1−dy), dx(1−dy), (1−dx)dy, and dxdy. This way, the weighted average changes smoothly with the source position, which reduces the abrupt steps of nearest neighbor sampling. It can also soften fine details, and it can't restore detail that was already blurred in the original photo.

On the trees output canvas, the median of three warp calls was 0.1 seconds for nearest neighbor and 0.2068 seconds for bilinear, so bilinear took about twice as long to run.

x0 = np.floor(x).astype(int)

Here, I use image rectification to turn a known square in the real world back into a square after taking a picture at an angle which warps its view due to perspective effects. I selected each visible corner in top-left, top-right, bottom-right, and bottom-left order, and then took the source pixel positions of each corner and remapped them to (0,0), (699,0), (699,699), and (0,699) by fitting a homography between them.

Both interpolation methods are shown for the entire warped photograph, with an outline and the four corner markers emphasizing that it is now a square. A 700x700 detail of the face itself is also shown. We can see that with nearest neighbor interpolation, the edges of the purple box around the Kleenex logo are somewhat jagged as the nearest neighbor is sometimes the purple interior and sometimes the differently colored exterior, which creates this artifact. However, the bilinear interpolation reduces this effect, but the edges of the Kleenex text seem less sharp.

Overall, the bilinear interpolation does create a higher quality image by the eye test as there aren't as many visible jagged edges, but the median runtime for the 700x700 detail was 0.0181s for nearest neighbor and 0.0417s for bilinear. For the whole frame result, the median runtime was 0.1051s for nearest neighbor and 0.2202 seconds for bilinear. This means that for the tradeoff of getting fewer jagged edges, we have to run an algorithm that takes more than 2x the amount of runtime.

A.4

Blend into a mosaic

For all three mosaics, the first source photo is warped into the second reference photo's projection using the recovered homography and bilinear interpolation. The common canvas covers both image footprints, and a separate validity mask identifies which pixels each image contributes. Simply letting the reference overwrite the warped source image creates an abrupt change at the image boundary if there are any differences in lighting or slight distortion of relationships that can't be captured by a single homography in the warped source image. Thus, I use feather blending, which means each original image receives weights based on distance from its edges, with larger weights towards the interior; these weights are warped with the corresponding image, multiplied by the validity mask, and then normalized by the sum of both images' weights. The final pixel color is thus their weighted average, and where only one image is valid, its color is completely preserved, and areas outside both images remain transparent. This makes the transition between the photos much more gradual as we can see with the visualization under the trees mosaic as to how the reference and the source blend together in terms of color contribution. Although this makes the transition between the photos more gradual, it is important to note that it does not fix geometric disagreement in any way. For example, the overwritten trees mosaic actually looks better than the feather blended version because the leaves between the images disagree, creating a blurred leaves artifact possibly due to the wind changing the position of the leaves between the photos or other residual misalignment. However, in the other two examples in the kitchen and living room, the feather blended version looks much better as there are slightly different brightness levels in each photo, which could reflect lighting or exposure differences. Feather blending can smooth these color differences, so the kitchen and living room images look a lot cleaner to me than the overwritten images, although geometric disagreement can still remain. Since the trees image has misaligned branches but not much color disagreement between photos, the overwritten mosaic looks better.

B.1

Harris corners and ANMS

Part B · automatic feature matching · 1600-pixel maximum input side · single scale · c = 0.9 · 1,000 selected corners per image

The first step in order to create a homography between the two images automatically is to find matching points between the images. Earlier, this was done manually, but now, this will be done algorithmically. I first convert each image to grayscale and use the provided Harris corner detector. Corners in general are useful because moving a small window in any direction will cause a significant shift in pixel values, so their positions can be identified in both directions. However, a flat background doesn't change much in either direction. The Harris detector gives a response at each pixel and the provided code selects local maxima while discarding points near the image boundary so there is enough room to extract a patch.

Now that we got candidate points and their magnitudes, simply just keeping the points with the largest Harris responses could just bunch up a lot of points in the same detailed part of the image, which isn't ideal since we are just going to be placing a lot of weight in very close points in the image that determines the entire homography. Thus, I want some sort of heuristic that balances taking points far from each other, so I used ANMS (adaptive non-maximal suppression) to achieve this effect of a more spread-out set of corners. This is done by calculating the distance to the closest corner whose response is sufficiently stronger, and then keeping 1000 corners with the largest distances. This way, a corner is more likely to be kept if there is no significantly stronger corner nearby.

B.2

Feature descriptors

40 × 40 axis-aligned window · Gaussian σ = 2 px · 5 × 5 block averages → 8 × 8 descriptor · mean 0 / standard deviation 1

Now that the corners are found, I need to implement some sort of algorithm so we can find these same corners in an image from a different view. In order to do this, I calculate descriptors of each corner. For each selected point, I use a 40x40 grayscale window from a blurred version of an image with a sigma of 2 pixels, and then average each 5x5 block to create an 8x8 patch. This is flattened to give a 64-value feature descriptor vector, which can be used to check similarity with other feature descriptors through methods such as SSD or cosine similarity.

Before comparing two descriptors, I demean the vector and standardize it to unit stddev. This is to reduce the effect of one photo being uniformly brighter or having a different positive contrast scaling than the other photo. Patches that are nearly constant (defined as having a stddev below 1e-6) are discarded because normalizing that to stddev of 1 would lead to numerical instability. These patches are all taken at the same scale and aligned with the image axes, so this method doesn't account for general rotation or scale changes between the photos.

B.3

Feature matching

Best / second-best squared descriptor distance < 0.6 · one source match per reference feature

Now, we have all relevant descriptors for matching. I just have to choose my distance metric and the threshold for accepting a match. For the algorithm, I used SSD or sum of squared differences, which adds up the elementwise squared differences between corresponding values in the two descriptors. However, just choosing the smallest SSD doesn't necessarily mean that the match is actually correct, since several parts of the image could look almost the same, especially with repeating patterns in an image. Thus, I find both the closest and second-closest descriptors, and keep the best match only if its SSD divided by the second-best SSD is below 0.6. If the two matches are almost equally good, this ratio would be closer to 1 and thus the match should be rejected since the solution is ambiguous.

If multiple source points from the first image choose the same reference point in the second image, I keep the match with the smallest ratio so that the reference point is only used once. After running this entire process, I had 280, 126, and 68 candidate matches for the trees, kitchen, and living room pairs, respectively. The lines in the figures connect the points chosen as matches between the two images. Some can still be incorrect because similar-looking patches don't necessarily correspond to the same point in the scene and can get past the threshold especially if there are slight scene geometric changes between the photos.

B.4

RANSAC and automatic mosaics

Four pairs per trial · forward reprojection threshold 3 px · 200–5,000 trials · confidence target 0.999 · seed 180 · consensus refit

In order to reconcile how there are still errors, I utilize the RANSAC algorithm to check whether the matches agree with one homography by selecting a large set of geometrically consistent matches. In order to do this, I randomly select four matching point pairs and estimate a homography from them, rejecting samples with degenerate geometry (such as samples where three points are nearly collinear). I also normalize the coordinates before solving the least squares system and then transform H back to the original image coords. For each estimated H, I project all of the source points into the reference image and measure their distance from the matched reference points. If it's below 3 pixels, the pair is counted as an inlier, and I keep the H with the most inliers, using the median inlier error to break ties. Then, I refit H using the inlier pairs and refine the set while it improves. This implementation uses a fixed random seed of 180, 200–5,000 trials, and an adaptive stopping target of 0.999 confidence based on the estimated inlier fraction.

Manual and automatic stitching

For all three mosaics, I use the automatically recovered homography to warp the first source photo into the second reference photo's projection, using the same inverse mapping and bilinear interpolation from part A. The main difference from part A is that the matching points are now automatically found through the algorithms above instead of manually picked. The automatic method produced a mosaic for all three pairs, but the living room pair had the smallest fraction of matches remaining after RANSAC, with only 23 of 68 matches agreeing with the final homography. Some alignment errors remain: there is some duplicating/blurring on the left couch edge in the manually picked mosaic, and while it is sharp in the automatically picked homography, we can see some blurring on the Amazon logo and box edge. The kitchen mosaic looks largely the same as the mosaic using manually picked points, with the perspective stretching on the fridge as the homography doesn't fix that. However, we see an improvement in the trees picture as there is significantly less overlap/blurring in the leaves where the two images meet in the mosaic with the automatically found points. This suggests that some of the error in the trees mosaic in part A could potentially be attributed to human error in picking the matching points since the automatic algorithm produces a sharper result here by decreasing those visual artifacts.
